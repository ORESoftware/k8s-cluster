# GitHub Projects and Linear projects by organization

This directory is the human-readable view of [`ops/portfolio/github-linear-project-registry.tsv`](../../ops/portfolio/github-linear-project-registry.tsv). The TSV remains the canonical governance source for the managed GitHub-organization fleet; this page is generated and checked in so humans and agents can resolve the correct GitHub Project and Linear project without reconstructing URLs or relying on display-name guesses.

The active 41-portfolio subset, including immutable Linear UUIDs, Slack channel IDs, ChatGPT project names, and `portfolio_key`, remains in [`ops/registries/portfolio-project-links.csv`](../../ops/registries/portfolio-project-links.csv). See [`github-linear-project-registry.md`](github-linear-project-registry.md) for the relationship between the 64-organization governance fleet and that active subset.

## Naming contract

- GitHub organization casing is canonical and must be preserved.
- The canonical GitHub Project title is `<organization>-project`.
- The canonical Project number is `1`, except `dancing-dragons`, which uses Project `4`.
- The Linear URL is copied exactly from the canonical TSV; do not infer it from the organization name.
- Provider joins use immutable native IDs or URLs first. Active portfolio automation additionally carries lowercase `portfolio_key`.
- Credentials, query parameters, fragments, ambiguous redirects, and ad hoc alternate Projects are forbidden.

## Maintenance

Regenerate and validate after changing the canonical TSV:

```bash
python3 scripts/ops/validate_github_linear_projects_by_org_doc.py --write
python3 scripts/ops/validate_github_linear_projects_by_org_doc.py
node scripts/ci/check-github-linear-project-registry.mjs
python3 scripts/ops/validate_github_linear_registry_relationship.py
```

The renderer is deterministic and network-free. Pull requests must contain both the registry change and the resulting directory update. Provider mutation remains a separate protected reconciliation operation; a green directory check proves declared mapping consistency, not that remote Projects or Linear metadata were changed.

The matching Linear workspace document is titled **GitHub Projects and Linear app links by organization**. The repository registry is authoritative when the two surfaces disagree; repair the Linear companion from reviewed registry evidence rather than editing provider identities independently.
