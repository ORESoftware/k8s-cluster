# Linear ↔ GitHub linking

Repository work must reference the relevant Linear issue identifier in the branch name, commit message, pull-request title, and pull-request body.

## Branch names

Prefer the branch name generated by Linear, for example:

```text
alexanderdmills/den-123-short-description
```

Branches must be cut from `main`. Avoid direct commits to `main` and avoid rebasing shared branches; merge `main` into the feature branch when synchronization is required.

## Commit messages

Use a non-closing relationship when an individual commit contributes to an issue:

```text
References DEN-123 describe the change
```

Other accepted non-closing forms include `Related to`, `Contributes to`, `Part of`, and `Towards`.

## Pull requests

Include the issue ID in the title. Use a closing word in the pull-request body only when merging the PR should complete the issue:

```text
Fixes DEN-123
```

Equivalent closing words include `Closes`, `Resolves`, and `Implements`.

Do not close an issue until required checks pass, review is complete, the PR is merged into `main`, and post-merge verification succeeds.

## Conflict resolution

Resolve conflicts semantically: merge the intent of both sides rather than merely choosing one side. Avoid `git rebase` in favor of `git merge`. After resolving, grep for conflict markers and repeat the review from the top as necessary.
